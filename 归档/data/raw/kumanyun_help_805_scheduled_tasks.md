## 一、计划任务概述

### 1. 定义

计划任务是一项使系统在规定时间自动执行某些特定任务的功能,在需要的情况下,您也可以方便地将其用于站点功能的扩展。

### 2. 核心特性

- **自动化执行**: 无需人工干预
- **定时触发**: 按设定时间/频率运行
- **系统集成**: 与系统核心紧密关联
- **功能扩展**: 可自定义任务脚本

---

## 二、重要警告

⚠️ **安全提示**

计划任务是与系统核心紧密关联的功能特性,不当的设置可能造成站点功能的隐患,严重时可能导致站点无法正常运行。

**请务必仅在以下情况下操作**:

1. 对计划任务特性十分了解
2. 明确知道正在做什么
3. 清楚操作的后果
4. 已做好数据备份

---

## 三、时间设置说明

### 时差处理

此功能与其他功能不同,完全按照站点系统默认时差对时间进行设定和显示,而不会依据某一用户或管理员的时差设定而改变显示或设置的时间值。

### 配置建议

- 使用服务器本地时间
- 避免频繁修改时区设置
- 与系统默认时区保持一致

## 六、任务执行方式

### 1. 手动执行

- **适用场景**: 问题排查、测试验证
- **操作**: 后台找到任务,点击【立即执行】
- **优点**: 即时生效
- **缺点**: 需要人工操作

### 2. 系统自动执行

#### 方式A: 访问触发

- **机制**: 用户访问网站时触发任务检查
- **优点**: 无需额外配置
- **缺点**:
  - 执行不准时(取决于访问量)
  - 占用用户访问时间

#### 方式B: Crontab定时触发(推荐)

**Linux服务器配置**:

```bash
# 编辑crontab
crontab -e

# 添加任务(每分钟检查一次)
* * * * * /usr/bin/php /www/wwwroot/yourdomain.com/crons/crons.php

# 或者每5分钟检查一次
*/5 * * * * /usr/bin/php /www/wwwroot/yourdomain.com/crons/crons.php
```

**Windows服务器配置**:

1. 打开【任务计划程序】
2. 创建基本任务
3. 触发器: 每5分钟
4. 操作: 启动程序
   - 程序: `C:\php\php.exe`
   - 参数: `C:\wwwroot\yourdomain.com\crons\crons.php`

## 七、任务状态管理

### 1. 启用/禁用

- **启用**: 任务按计划自动执行
- **禁用**: 任务暂停,不再执行
- **应用**: 临时关闭某些任务

### 2. 执行日志

- **查看位置**: 【计划任务管理】→【执行日志】
- **日志内容**:
  - 执行时间
  - 执行结果
  - 错误信息
  - 执行耗时

### 3. 异常监控

- **超时未执行**: 检查Crontab配置
- **执行失败**: 查看错误日志
- **执行耗时过长**: 优化脚本性能

## 八、自定义任务开发

### 1. 任务脚本规范

```php
<?php
/**
 * 自定义计划任务示例
 * 文件位置: /crons/custom_task.php
 */

// 载入系统核心
define('IN_CRONLITE', TRUE);
require(dirname(__FILE__).'/../data/config.inc.php');

// 开始时间
$start_time = microtime(true);

// 任务逻辑
try {
    // 1. 数据查询
    $sql = "SELECT * FROM table WHERE status = 1";
    $result = DB::query($sql);

    // 2. 数据处理
    foreach($result as $row) {
        // 处理逻辑
    }

    // 3. 记录日志
    $log = "执行成功,处理 ".count($result)." 条数据";

} catch (Exception $e) {
    // 错误处理
    $log = "执行失败: ".$e->getMessage();
}

// 计算耗时
$exec_time = microtime(true) - $start_time;
$log .= ",耗时: ".round($exec_time, 2)."秒";

// 写入日志
file_put_contents(
    dirname(__FILE__).'/../data/logs/custom_task.log',
    date('Y-m-d H:i:s')." - ".$log."\n",
    FILE_APPEND
);
?>
```

### 2. 任务添加步骤

1. **编写脚本**:
   - 放置在 `/crons/` 目录
   - 遵循命名规范: `任务名称.php`

2. **后台添加**:
   - 进入【计划任务管理】
   - 点击【添加任务】
   - 填写任务信息:
     - 任务名称
     - 执行脚本
     - 执行频率
     - 开始时间

3. **测试执行**:
   - 手动执行验证
   - 检查日志输出
   - 确认功能正常

4. **正式启用**:
   - 设置为启用状态
   - 监控执行情况

## 九、性能优化

### 1. 任务分散执行

**避免**:

```
所有任务都在凌晨00:00执行
→ 造成服务器负载峰值
```

**推荐**:

```
00:00 - 会员等级更新
01:00 - 统计数据更新
02:00 - 数据库备份
03:00 - 缓存清理
04:00 - 过期信息处理
05:00 - sitemap生成
```

### 2. 高频任务优化

对于频繁执行的任务(如每分钟/每5分钟):

- 减少数据库查询次数
- 使用缓存机制
- 避免复杂计算
- 限制处理数据量

### 3. 长时任务处理

对于耗时长的任务:

- 分批处理数据
- 设置超时时间
- 使用队列机制
- 记录执行进度

## 十、故障排查

### 问题1: 任务未执行

**检查项**:

1. Crontab配置是否正确
2. PHP路径是否正确
3. 文件权限是否足够(755)
4. 任务是否启用状态

### 问题2: 任务执行报错

**排查步骤**:

1. 查看执行日志
2. 检查错误信息
3. 验证数据库连接
4. 确认文件路径正确

### 问题3: 任务执行缓慢

**优化方向**:

1. 添加索引优化查询
2. 减少循环嵌套
3. 使用批量操作
4. 清理历史数据

---

## 十一、最佳实践

### ✅ 推荐做法

1. **备份优先**:
   - 修改任务前先备份
   - 保留原始配置

2. **小步测试**:
   - 先测试后上线
   - 从小数据量开始

3. **日志记录**:
   - 详细记录执行过程
   - 保留足够历史日志

4. **异常通知**:
   - 设置邮件/短信告警
   - 及时发现问题

5. **定期检查**:
   - 每周review执行日志
   - 优化低效任务

### ❌ 避免做法

1. 不要在生产环境直接测试新任务
2. 不要设置过于频繁的执行频率
3. 不要忽略任务执行错误
4. 不要在高峰期执行重任务
5. 不要随意修改系统内置任务

---

## 十二、应急预案

### 场景1: 任务执行导致系统卡死

**应急处理**:

1. 立即禁用该任务
2. 重启PHP-FPM/Apache
3. 检查任务代码
4. 优化后重新测试

### 场景2: 数据被误删

**恢复步骤**:

1. 停止相关任务
2. 从备份恢复数据
3. 修复任务逻辑
4. 验证数据完整性

---

**维护建议**:

- 每月检查一次计划任务执行情况
- 定期清理无用任务
- 保持任务脚本简洁高效
- 做好文档和注释
