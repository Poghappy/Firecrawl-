## 一、用户无法注册/登录问题

### 问题1.1: 用户点击注册无反应

**症状**:

- 点击注册按钮后页面无任何变化
- 或者一直显示"加载中"

**可能原因及解决方案**:

#### 原因A: 验证码问题

```
检查路径: 后台 → 系统 → 基本设置 → 网站安全设置 → 验证码设置

排查步骤:
  1. 查看浏览器控制台(F12)是否有JS错误
  2. 检查验证码图片是否正常加载
  3. 尝试更换验证码类型(图形验证码 ↔ GeeTest极验)

解决方案:
  - 方案1: 清除浏览器缓存重试
  - 方案2: 检查服务器GD库是否安装
    bash: php -m | grep gd
  - 方案3: 临时关闭验证码测试(确认后重新开启)
```

#### 原因B: 注册间隔时间限制

```
检查路径: 网站安全设置 → 注册间隔时间

症状: 同一IP短时间内多次尝试注册

解决方案:
  - 更换IP地址或等待间隔时间后重试
  - 调整注册间隔时间(建议60-180秒)
  - 清除该IP的注册限制记录
```

#### 原因C: 短信验证码发送失败

```
检查路径: 系统 → 短信系统 → 短信发送日志

排查步骤:
  1. 查看短信发送日志,确认是否发送成功
  2. 检查短信平台余额是否充足
  3. 验证短信签名和模板是否审核通过

解决方案:
  - 充值短信平台余额
  - 重新配置短信参数
  - 联系短信服务商排查
```

### 问题1.2: 注册提示"用户名已存在"

**症状**:

- 明明是新用户名,却提示已存在
- 或者无法使用某些特定用户名

**可能原因及解决方案**:

#### 原因: 用户名在保留列表中

```
检查路径: 网站安全设置 → 保留用户名

解决方案:
  - 查看保留用户名列表
  - 如非必要,从列表中移除该用户名
  - 引导用户更换其他用户名

常见保留用户名:
  admin, administrator, root, system, test, guest,
  visitor, 管理员, 系统, 测试, 游客
```

### 问题1.3: 登录提示"账号已被锁定"

**症状**:

- 用户无法登录,提示账号被锁定
- 即使密码正确也无法登录

**可能原因及解决方案**:

#### 原因A: 密码错误次数过多

```
检查路径: 网站安全设置 → 登录错误锁定

配置信息:
  错误次数: X次
  锁定时间: Y分钟

解决方案:
  - 方案1: 等待锁定时间结束(自动解锁)
  - 方案2: 后台手动解锁
    路径: 用户 → 用户管理 → 用户列表 → 编辑 → 解除锁定
  - 方案3: 数据库直接解锁
    SQL: UPDATE fb_user SET login_error_count=0 WHERE username='xxx';
```

#### 原因B: IP被封禁

```
检查路径: 网站安全设置 → IP访问限制

解决方案:
  - 查看IP黑名单
  - 移除用户IP
  - 建议不要轻易封禁IP(可能封禁整个公司/小区)
```

## 二、外卖订单显示异常

### 问题2.1: 商家店铺打开显示为代码

**症状**:

- 点击外卖商家店铺,页面显示乱码或PHP代码
- 或者显示为空白页面

**根本原因**:
外卖订单分表任务未执行

**解决方案(100%有效)**:

```
路径: 系统 → 基本设置 → 计划任务管理

步骤:
  1. 找到任务: waimaiorder_syncFenbiao.php
  2. 点击【立即执行】
  3. 等待执行完成(可能需要1-5分钟)
  4. 刷新前台商家页面验证

预防措施:
  - 确保该任务每天自动执行
  - 建议执行时间: 凌晨2:00
```

### 问题2.2: 配送员不显示

**症状**:

- 外卖订单派单时,找不到配送员
- 配送员列表为空

**可能原因及解决方案**:

#### 原因A: 同样是分表问题

```
解决方案: 执行外卖订单分表任务(同问题2.1)
```

#### 原因B: 配送员未开工

```
检查路径:
  - 后台: 模块 → 美食外卖 → 配送员管理 → 配送员列表
  - 配送员APP: 点击"开始接单"

解决方案:
  - 通知配送员开工
  - 或后台手动设置配送员状态为"工作中"
```

#### 原因C: 配送范围不匹配

```
检查项:
  - 配送员的服务范围
  - 订单的商家位置

解决方案:
  - 调整配送员服务范围
  - 或安排其他配送员
```

## 三、支付相关问题

### 问题3.1: 微信支付提示"当前页面的URL未注册"

**症状**:

- 用户发起支付后,提示URL未注册
- 或者支付页面报错

**根本原因**:
微信公众号/小程序未配置支付授权目录

**解决方案**:

```
步骤1: 登录微信商户平台
  网址: pay.weixin.qq.com

步骤2: 进入支付配置
  路径: 产品中心 → 开发配置 → 支付配置

步骤3: 添加支付目录
  JSAPI支付授权目录:
    https://yourdomain.com/payment/wechat/
    https://yourdomain.com/api/pay/

  注意:
    - 必须是https
    - 必须以/结尾
    - 最多可添加5个目录

步骤4: 配置域名白名单
  路径: 产品中心 → 开发配置 → 公众号支付
  支付回调域名: yourdomain.com
```

### 问题3.2: 支付宝支付报错"sign check error"

**症状**:

- 发起支付宝支付时报签名错误
- 或者支付后回调失败

**可能原因及解决方案**:

#### 原因A: 公钥/私钥配置错误

```
检查路径: 系统 → 基本设置 → 支付方式设置 → 支付宝

检查项:
  ✓ AppID是否正确
  ✓ 应用私钥是否完整(包含header/footer)
  ✓ 支付宝公钥是否为最新

解决方案:
  1. 登录支付宝开放平台
  2. 应用管理 → 查看应用详情
  3. 重新下载/上传公钥
  4. 复制最新的支付宝公钥到后台
```

#### 原因B: 接口加签方式不匹配

```
检查项:
  - 支付宝开放平台: RSA2(SHA256)
  - 后台配置: 必须选择RSA2

解决方案:
  - 统一使用RSA2加签方式
```

### 问题3.3: 支付成功但订单状态未更新

**症状**:

- 用户已支付成功
- 但订单仍显示"待支付"

**可能原因及解决方案**:

#### 原因A: 支付回调URL无法访问

```
检查项:
  - 回调URL是否可公网访问
  - 服务器防火墙是否拦截
  - Nginx/Apache配置是否正确

排查方法:
  curl https://yourdomain.com/api/notify/wechat/

解决方案:
  - 确保回调URL可访问
  - 检查支付平台通知记录
```

#### 原因B: 回调处理失败

```
检查路径:
  - 数据库: fb_pay_log (支付日志表)
  - 日志文件: /data/logs/pay.log

解决方案:
  - 查看错误日志
  - 手动补单(后台修改订单状态)
  - 修复代码Bug后重新推送回调
```

## 四、短信验证码问题

### 问题4.1: 用户收不到验证码

**症状**:

- 用户点击获取验证码后,迟迟收不到短信
- 或者提示发送成功但实际未收到

**排查流程图**:

```
收不到验证码
    ↓
查看短信发送日志
    ↓
发送成功? ─ 否 → 检查短信平台配置
    ↓ 是          - 账号余额
查看手机号段           - 签名/模板
    ↓              - 接口参数
支持的运营商? ─ 否 → 联系短信服务商
    ↓ 是
检查短信内容
    ↓
包含违禁词? ─ 是 → 修改短信模板
    ↓ 否
联系用户检查
    - 信号是否正常
    - 是否被拦截(垃圾短信)
    - 是否设置短信拦截APP
```

### 问题4.2: 短信发送频繁报错

**症状**:

- 短信发送日志大量失败记录
- 提示"超过频率限制"

**可能原因及解决方案**:

#### 原因A: 触发短信服务商频率限制

```
常见限制:
  - 同一手机号: 1条/分钟, 5条/小时, 10条/天
  - 同一IP: 100条/小时
  - 同一签名: 1000条/小时

解决方案:
  - 前端增加倒计时(60秒后才能重发)
  - 后端限制同一手机号发送频率
  - 联系服务商提高配额
```

#### 原因B: 恶意刷短信

```
症状:
  - 短时间大量注册
  - 短信余额快速消耗

解决方案:
  - 开启图形验证码(发送短信前)
  - 增加注册间隔时间
  - IP黑名单封禁
  - 启用GeeTest行为验证
```

## 五、城市分站问题

### 问题5.1: 新建城市后前台无法访问

**症状**:

- 后台新建了城市分站
- 但访问分站域名显示404

**可能原因及解决方案**:

#### 原因A: DNS解析未配置

```
检查项:
  - 主域名: example.com ✓
  - 泛解析: *.example.com ?

解决方案:
  登录域名服务商(阿里云/腾讯云):
  1. 添加A记录
     主机记录: *
     记录值: 服务器IP
  2. 等待DNS生效(10分钟-2小时)
  3. 验证: ping beijing.example.com
```

#### 原因B: Nginx配置问题

```
检查: /www/server/nginx/conf/vhost/example.com.conf

server_name应包含:
  server_name example.com *.example.com;

解决方案:
  1. 修改Nginx配置
  2. nginx -t (测试配置)
  3. nginx -s reload (重载配置)
```

#### 原因C: 分站未启用

```
检查路径: 系统 → 基本设置 → 城市分站设置

解决方案:
  - 编辑城市
  - 状态改为"启用"
  - 保存
```

### 问题5.2: 多城市后模块无法绑定独立域名

**症状**:

- 开启2个以上城市分站后
- 模块绑定域名功能消失

**原因**:
系统设计限制,多城市与模块独立域名互斥

**解决方案**:

```
方案A: 保留单城市(推荐新站)
  - 只保留1个主营城市
  - 模块可绑定独立域名
  - 适合: 区域性运营

方案B: 使用子域名访问(推荐成熟站)
  - 保留多城市
  - 模块使用子域名访问
  - 例如: house.example.com/beijing/
  - 适合: 全国性运营
```

## 六、计划任务问题

### 问题6.1: 计划任务未执行

**症状**:

- 后台任务显示"待执行"
- 任务执行时间一直不更新

**排查步骤**:

#### 步骤1: 检查Crontab配置

```bash
# 查看crontab
crontab -l

# 期望看到:
*/5 * * * * /usr/bin/php /www/wwwroot/example.com/crons/crons.php

# 如果没有或不正确,重新配置:
crontab -e
# 添加上述行后保存
```

#### 步骤2: 检查PHP路径

```bash
# 查找PHP可执行文件位置
which php

# 常见路径:
/usr/bin/php
/usr/local/bin/php
/www/server/php/74/bin/php  (宝塔)

# 如路径不对,修改crontab中的PHP路径
```

#### 步骤3: 检查文件权限

```bash
# 计划任务脚本必须有执行权限
chmod 755 /www/wwwroot/example.com/crons/*.php

# 检查
ls -lh /www/wwwroot/example.com/crons/
```

#### 步骤4: 手动执行测试

```bash
# 手动执行看是否有报错
/usr/bin/php /www/wwwroot/example.com/crons/crons.php

# 查看输出,排查错误
```

### 问题6.2: 任务执行报错

**常见错误及解决方案**:

#### 错误A: "Fatal error: Maximum execution time exceeded"

```
原因: 脚本执行超时

解决方案:
  1. 修改php.ini
     max_execution_time = 300 (默认30秒,改为300秒)

  2. 或在脚本中设置
     set_time_limit(300);

  3. 优化任务代码,减少执行时间
```

#### 错误B: "Allowed memory size exhausted"

```
原因: 内存不足

解决方案:
  1. 修改php.ini
     memory_limit = 512M (默认128M,改为512M)

  2. 或在脚本中设置
     ini_set('memory_limit', '512M');

  3. 优化代码,减少内存占用
```

## 七、性能与速度问题

### 问题7.1: 网站打开很慢

**症状**:

- 首页加载时间超过5秒
- 用户体验差,跳出率高

**排查与优化**:

#### 优化1: 启用Redis缓存

```
路径: 系统 → 基本设置 → 缓存优化配置

前提: 服务器已安装Redis

配置:
  Redis主机: 127.0.0.1
  Redis端口: 6379
  状态: ✅ 启用

效果: 可提升50%-300%性能
```

#### 优化2: 开启CDN加速

```
推荐CDN:
  - 阿里云CDN
  - 腾讯云CDN
  - 七牛云

加速内容:
  - 静态资源(CSS, JS, 图片)
  - 模板文件

效果: 减少50%-80%加载时间
```

#### 优化3: 图片优化

```
问题: 图片过大(单张>1MB)

解决方案:
  1. 开启图片水印(自动压缩)
  2. 限制上传图片大小(建议500KB)
  3. 使用WebP格式
  4. 启用图片懒加载
```

#### 优化4: 数据库优化

```bash
# 慢查询日志
tail -f /var/log/mysql/slow.log

# 常见问题:
  - 缺少索引
  - 无where条件的全表扫描
  - join过多

# 解决:
  - 添加索引
  - 优化SQL语句
  - 定期清理历史数据
```

## 八、数据丢失问题

### 问题8.1: 用户信息/订单丢失

**紧急处理流程**:

```
发现数据丢失
    ↓
立即停止系统运行 (避免覆盖)
    ↓
检查数据库备份
    ↓
有备份? ─ 是 → 恢复最近备份
    ↓ 否
检查服务器快照
    ↓
有快照? ─ 是 → 恢复快照
    ↓ 否
联系云服务商技术支持
(可能有数据恢复服务)
```

### 问题8.2: 数据库备份失败

**症状**:

- 计划任务显示备份失败
- 备份文件夹为空

**可能原因及解决方案**:

#### 原因A: 磁盘空间不足

```bash
# 检查磁盘空间
df -h

# 如果使用率>90%,清理:
  - /data/logs/ (日志文件)
  - /data/cache/ (缓存文件)
  - /data/backup/ (旧备份文件)
```

#### 原因B: 数据库用户权限不足

```sql
-- 检查权限
SHOW GRANTS FOR 'firebird'@'localhost';

-- 如缺少权限,重新授权:
GRANT ALL PRIVILEGES ON firebird_portal.* TO 'firebird'@'localhost';
FLUSH PRIVILEGES;
```

## 十、其他常见问题

### 问题10.1: 后台登录后一直跳转登录页

**原因**: Session无法保存

**解决方案**:

```
方案1: 检查session目录权限
  chmod 777 /tmp/  (Linux)
  或
  chmod 777 /www/wwwroot/example.com/data/sessions/

方案2: 修改session配置
  php.ini:
    session.save_path = "/www/wwwroot/example.com/data/sessions"

方案3: 清除浏览器Cookie
```

### 问题10.2: 图片上传失败

**可能原因**:

```
原因1: upload目录权限不足
  chmod -R 777 /www/wwwroot/example.com/upload/

原因2: PHP上传大小限制
  php.ini:
    upload_max_filesize = 10M
    post_max_size = 10M

原因3: Nginx限制
  nginx.conf:
    client_max_body_size 10M;
```
